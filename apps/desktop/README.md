# Sornio Windows app — local review 0.2.0

This is the first implementation of the Windows plan discussed on 26 October:
an independent React/Tauri app with bundled screens, native encrypted SQLite,
then offline business commands, LAN, cloud and Android. The older
`desktop/windows` package is a connected WebView review host; it is not this app.

## Run on Windows

Install Node 24, Rust stable and Microsoft's C++ build tools. From this folder:

```sh
npm ci
npm run desktop:dev
npm run desktop:build
```

The NSIS setup is under `src-tauri/target/release/bundle/nsis`. It is an unsigned
engineering review, with its own application identity and data directory.
The WebView2 offline installer is included, so setup does not need to fetch
the browser runtime. No public download is configured by this change.

The Vite development server is a local development tool. Opening it in a normal
browser refuses local storage access; there is no browser database fallback.
Production assets are embedded in the Windows binary, not loaded from Vercel.

## What works

- Open the bundled workspace without the public website or a Next.js server.
- Save and reopen a sample business draft using SQLCipher-encrypted SQLite.
- Keep the random database secret in Windows Credential Manager, never JavaScript,
  environment variables, the package, or a plaintext sidecar file.
- Serialize first-use key provisioning; refuse missing keys, unreadable stores,
  newer schemas and failed writes without deleting/resetting records.
- Use committed revisions to reject stale writes from a second window/process.
- Set up a local password, lock this app instance and unlock it offline. Every
  native draft command checks the native session, not a renderer role/flag.
  Reopening the app always starts locked. Five wrong attempts trigger a 60-second
  wait stored in the encrypted database, including across process restart.
- Store only a randomly salted Argon2id password hash (19 MiB, two iterations,
  one lane). Verification accepts only the bounded format generated by this
  app. The password does not derive or replace the SQLCipher key. The native
  command zeroizes its owned password string when it completes. Other IPC/runtime
  copies are not guaranteed to be wiped; JavaScript form strings are cleared
  without a promise of deterministic memory erasure.
- Keep the latest 20 saved draft copies in the same encrypted database. Restore
  an earlier copy as a new revision; both the current draft and history commit
  together. Version-one drafts migrate without losing their original content.
- Reopen the latest committed draft after a conflict, with an explicit discard
  step when the window has unsaved edits. Failed reopen keeps those edits.

Commands accept a bounded draft and expected revision, never SQL, filenames,
keys, URLs or an arbitrary tenant. Native permissions belong only to the bundled
main window. No filesystem, shell, HTTP or SQL plugin is exposed to the UI.

## Limits

Test data only. This does not import or replace the existing account database.
It has no business identity verification, staff roles, production
onboarding, billing, signed entitlements, sync, device-loss backup/key recovery or printing.
Saved copies protect against unwanted draft edits; they share the database and
are not a backup for database corruption or a lost device.
The password gate is local review access, not verified owner onboarding or a
production account. It offers explicit lock and restart locking, without idle
auto-lock, password change/reset or remote session revocation yet. Forgotten
passwords are not silently reset. Missing access records fail closed.
Encryption currently protects one review workspace per Windows user; it does
not yet implement per-business/staff separation. Software executing as that
Windows user may access its Credential Manager. Losing that Windows profile
can make the draft unrecoverable; backup/key recovery is a later release gate.

The review UI is English only. Existing web language catalogs remain unchanged;
desktop language parity is required before customer release. It is a storage
foundation, not a completed port of the eight business consoles.

## Checks

```sh
cargo test --locked --manifest-path ../../packages/local-store/Cargo.toml
npm run build
```

The first command tests real SQLCipher storage and survives process close/reopen,
wrong keys, stale writers, validation, failed writes and newer-schema refusal.
Recovery tests cover v1 migration, restore/reopen, stale restore rejection,
retention and rollback of both the draft and history when a history write fails.
On Windows this also includes a Credential Manager test using a temporary,
separate vault entry; missing credentials must never cause key replacement.
The Windows workflow also produces a review setup and native-screen captures.
It uses Windows accessibility automation on the normal release binary with
outbound firewall rules for the app and WebView. It does not enable a debugging
port or use a browser-only substitute for native acceptance.

The native test now covers offline password setup, manual lock/unlock, wrong
password refusal after forced termination, and successful unlock with the
restored draft retained. The browser workflow runs `check-ui.cjs` with isolated
Playwright tooling against the desktop Vite server. That harness mocks IPC to
check interaction/error handling; it cannot establish native authorization.

Password API reference: [RustCrypto Argon2 0.5.3](https://docs.rs/argon2/0.5.3/argon2/).

# Local stock review 0.3.0

The bundled app now supports sample items and counted stock in encrypted local
tables. Add prices in paise and counts in thousandths; record deliveries or
corrections with a reason. Native unlock is required for all commands. Mutation
and append-only history commit together; stable operation IDs deduplicate exact
retries, while revision checks reject stale stock adjustments. A draft restore
does not rewind inventory. This remains one test workspace per Windows profile.

This is not production billing, verified owner onboarding, staff roles, business
isolation, backup or sync. See `docs/reviews/2026-10-27-windows-stock.md` for scope
and validation. Native acceptance adds fractional item/stock save and count
retention after forced termination/unlock.
