2. POLICY NOW ENFORCED (each has a negative test in scripts/test-windows-foundation-evidence.mjs)
   - 'blocked' is rejected on W-01..W-12 even when a reason is supplied.
   - 'blocked' is honoured only on H-13..H-15, where a reason of >=8 chars is required.
   - environment.webview2='present' is rejected: W-02 is unexercisable on such a workstation.
   - schemaBefore/schemaAfter are pinned to 12/13 (const in the schema); 11->13 and 12->14 refused.
   - schemaBefore/schemaAfter must be integers: '13' as a string is refused, not coerced.
   - financial snapshot fields must be integers: '10164' and 1500.5 are refused.
   - stockMilli needs >=3 products, the SAME ids on both sides, and no placeholder ids.
   - lastInvoiceNumber 'REPLACE' is refused; downstream drift in outstanding is caught.
   - evidence rows must be non-empty strings: '   ' and a bare string are refused.
   - hardwareClaimed values must be booleans; a non-boolean claim is refused.
   - nonClaims must disclose BOTH the unsigned build and the unexecuted hardware gates.
   - commitSha '0'x40 is rejected as a placeholder, and a non-HEAD SHA is rejected as stale.
   - a missing git checkout is reported as a failure, not an uncaught crash.

5. SCHEMA AND VALIDATOR AGREE (structural policy, not just prose)
   The gates node is no longer a single patternProperties rule: each of the 15 gates has its own
   schema node, and W-01..W-12 enumerate only [passed, failed, not-run] - so a blocked foundation
   gate is invalid by construction, not only by a validator branch. Checked with ajv (the only
   JSON Schema engine present at node_modules/ajv@6.15.0, run draft-07-mode with $schema dropped;
   the constructs used - type/const/enum/minLength/minProperties/additionalProperties/required -
   are shared with 2020-12 and the document declares 2020-12):
   REJECT  shipped template (worksheet with placeholders - expected REJECT)
   REJECT  W-02 blocked WITH a reason (must REJECT)
   REJECT  H-13 blocked with NO reason (must REJECT)
   REJECT  schema 12 -> 14 (must REJECT)
   REJECT  schemaAfter as a string (must REJECT)
   REJECT  one stock product (must REJECT)
   REJECT  blank evidence row on a passed gate (must REJECT)
   REJECT  unknown gate name (must REJECT)
   REJECT  non-boolean hardware claim (must REJECT)
   ACCEPT  valid-shaped record (expected ACCEPT at schema level)

   The shipped example is deliberately NOT a validating record: it is a worksheet. What the
   template check enforces is narrower and unchanged in spirit - the example must keep only the
   hardware gates blocked, must claim no hardware, and must model schema 12 -> 13.
