# Phase 18E — preparation history increment

Stacked on staff management (`feature/phase18e-kitchen-staff-history`, `d74f3849918111e95ae791cc913423d2562cf25a`, draft #175), which depends on verified Phase 18D #174. No merges or releases.

Native history reads the existing immutable restaurant transition events and the new assignment journal through one bounded query. It searches ticket/order/table/takeaway/item/staff references, recorded preparation state and inclusive UTC date ranges. Pages return at most 50 events (25 by default) using timestamp-plus-event-ID keysets, including ties at the same timestamp. Newer events do not shift an older page through offset pagination. Staff/business/session checks are native; no financial commands are exposed. `Served` transitions provide their actual recorded completion timestamps. Old tickets without a stored transition do not receive invented Pending or completion events. Assignment events have no invented preparation-state snapshot.

Desktop uses the existing native kitchen command infrastructure. Android/iOS/iPadOS use the existing pinned HTTPS session transport with a read-only `/v1/kitchen-history` route added to both native allowlists. Search controls and Older events are adapted to existing layouts. Previous results are retained when a refresh fails. Read queries are safely repeatable and do not need a financial-operation queue. Staff grants and preparation updates continue to use the separate existing authorization/recovery mechanisms.

Payment status and staff display names are current values, not reconstructed historical snapshots. The UI explicitly labels current paid/unpaid state and UTC dates. Paid preparation remains distinct from financial settlement and current table occupancy.

Passed: desktop TypeScript/Vite build; mobile TypeScript; all 63 shared-domain tests (two new history response cases); 63 mobile and 38 desktop contract checks; 92 migration/schema checks; actual native history SQL against migrated SQLite, including bounded keyset pages with equal timestamps, combined search/date/status filters, existing completion events and no fabricated initial events. Prior staff/paid-kitchen SQL tests remain passing. Rust/native platform execution is still unavailable and is not claimed.

Remaining: mobile supervisor assignment writes (desktop supervisors can assign now), encrypted restart recovery for desktop assignment requests, end-to-end installed-platform/LAN verification and native Rust/SQLCipher/RBAC tests. History response pages are bounded, but large-history query performance and indexing need installed-volume measurement. The current query searches stored menu descriptions and current employee names; it does not recover historical product/staff names that were never stored. All production financial, installer and lifecycle gates remain mandatory.
